**研究で問うこと**：利用者は何を期待し、何を理解し、どこでつまずき、どこに不快・圧力を感じ、何を面白いと感じたか。測らないこと：占いの科学的妥当性、心理診断の信頼性、未来の実現、過去の出来事の的中、販促KPI、実売上。

## 3. 募集条件・人数・偏りへの対策（D/I）

### A群：無料5問と現在の文章

- **初期案：5〜8名**（既存M09-USER-REVIEWの目安を維持）。目的は重大な誤読・操作のつまずき発見であり、統計的有意差や市場代表性の推定ではない。
- 18歳以上の自主参加者。年齢・性別・職業は採用条件として固定しないが、MK01のP-Aに近い「占いを自分を振り返る材料として使ったことがある」人を中心候補とし、診断が苦手な人や初見者も含める。
- **関係の偏りを記録**：親しい友人・Threadsフォロワー・知人だけに偏ると褒める回答が増える可能性。関係性は本人から聞いた粗い区分（知人／SNS経由／初見）だけを内部で管理し、公開レポートに個人特定可能な組合せを書かない。
- 機器・操作条件：スマートフォン優先（機種を収集せずOSカテゴリだけ任意）、PCやキーボード操作も含める。必要な支援・読み上げは参加者が希望した場合に相談し、病歴等を聞かない。
- **明確な除外**：未成年者、現在この商品の開発・添削を担う人、同意説明を理解しないまま実施を求められる状態。回答しない・参加しない自由を保障する。参加への対価を好意的レビューと結びつけない。
- **既存の過去無料鑑定枠やフォロワーを自動参加者と数えない**。新たな参加希望と独立同意が必要。

### B群：有料候補の物語見本・説明（非個人・非販売）

- **初期案：4〜6名**。別の参加者でもA群と同じ人でもよいが、どちらの刺激文を先に読んだかを記録し、順序効果を論じられるほどのサンプル数ではない点を明示。
- **本人の生年月日、出生場所、出生時刻、実際の転機・病歴・恋愛事情を尋ねない**。文章・商品説明は誰の経験でもない架空例だけ。
- 本物の個人鑑定であるかのように提示しない。P00商品構想の分かりやすさ、読後の理解、無料との違い、誇大な期待が生まれないかを検査する。
- 価格の反応を聞く場合、MK04の候補1,980／2,980／3,980円を**仮の設計案**と明示し、提示順を参加者間で切替。これは支払意思の探索であって、実購入検証・価格決定・販売開始ではない。
- 有料の本番暦文章の評価は、M06/N01/N05のG2-C/S検証と正式な安全な研究環境ができるまで**別の将来工程**に保留。

### 募集と対価

- 募集経路は**検討のみ**：任意の直接依頼、既知の参加協力者、後日の公開募集中ページ。運営主体・窓口・個人情報の利用目的・管理方法の確定前にSNS公募しない。
- 対価を設けるなら**拘束時間への謝礼**として実際の条件・実施前説明を確定。好意的回答や購入・フォロー・投稿を条件としない。途中終了・批判的回答でも不当に謝礼を取り消さない。
- 希望者にだけ再連絡の許可を個別取得。**調査参加同意はメール広告の承諾ではなく、MK07 CRMへ自動登録しない**。
- 募集から見送りまでの参加者の意思とデータ処理を個別に確認。未回答理由を追及しない。

## 5. インタビュー／ユーザーテスト実施手順（D）

### 事前準備（担当者用・実施未着手）

1. M09-REVIEW-PACKETのA〜Fシナリオとプレビュー版を固定。F（正式scene_v01画像）は**未完成のため評価不可**。文字による代替を明示し、画像版の実感と混同しない。
2. 担当者がローカルブラウザで自分の端末を操作し、Q1〜Q5の戻る・x・終了を事前確認。既存Chromium25合格は別時点のコードに対する記録。今の端末での試験結果を別途記録。
3. 募集文・用途説明・同意版・運営窓口・謝礼条件・保管先・削除方法を確定。公開SNSで対象を募るのは別承認が必要。
4. 実施の練習を内部で行い、質問の誘導や参加者の負担を調整。**研究者の内部練習と実参加者レビューを混ぜない**。
5. 参加者がアクセスしやすい場所・端末・補助手段を選び、公開していないコード／URL・個人データの無断共有を防ぐ。

### A群：無料診断（約20〜30分・仮）

| 進行 | 課題と司会の行動 | 記録（個人回答は保存しない） |
| --- | --- | --- |
| 00 導入 | この作品は開発途中、占いの的中を確認する調査ではないことを説明。中断・保留・録音なしを再確認 | 同意版／説明確認／開始可否 |
| 01 期待 | 「この見出しから、どんな内容が出ると思いましたか？」（まず自然な第一印象） | 無料の期待・誤読を論点化 |
| 02 5問操作 | 「5問を進め、読み終えたところまでやってみてください」。解き方を教えず詰まる箇所を観察 | 到達・途中中断・戻る・xの発見。**Q回答IDは保存しない** |
| 03 結果説明 | 「この結果は何を言っているように感じましたか？」「どこからそう読みましたか？」 | 理解の根拠と違和感をコード化 |
| 04 保留 | 既存パケットのタイプ保留B・全問xのCを**架空シナリオ**として見せる。「この画面を見たらどう感じますか？」 | タイプなしへの置き去り感、誤解 |
| 05 選べる問い | 「最後の問いは、どう扱いたいと思いましたか？」 | 実践強制の感覚や自由に無視できる印象 |
| 06 評価票 | 後述A群フォーム。困った言葉や違和感は自由回答・スキップ可 | 5段階＋任意メモ |
| 07 終了 | 受けた印象、修正したほうがよいところ、データ削除・撤回窓口を確認 | 再テストや追加連絡は別希望者のみ |

### B群：有料候補の架空物語・LPコンセプト（約15〜25分・仮）

1. 試作商品を販売していないこと、実在人物の運命を示していないことを説明。
2. **先に**架空の商品の短い紹介と、非個人の架空物語見本を読み、理解を自由に説明してもらう。根拠のない具体年や的中例を避ける。
3. 「これは何が手元に残る商品だと思いましたか」「無料5問と何が違うと考えましたか」を自由回答。
4. 「読みにくいところ／決めつけに感じるところ／作り物として誤認しそうなところ」を聞く。
5. 価格感度を扱う場合のみ、MK04の3つの**仮価格**を順序を入れ替えて提示。「買いますか？」より「この説明では何が足りず判断しにくいですか」と聞く。**実購入や販売実績にしない**。
6. B群の評価票を記入。本人に過去の出来事、出生情報、トラウマを聞き出さない。
7. 出典・象徴・独自解釈の違いが伝わったか、納品・返金・相談の条件が不明なら未決定と受け止められたかを確かめる。

### インタビューで使う言葉と使わない言葉

- 使用：「どんなふうに受け取りましたか」「迷った箇所はどこですか」「もし違うと感じたらどうしますか」「ほかの選択肢はありますか」
- 禁止：「すごく当たっていますよね」「安心しましたよね」「この商品なら2,980円払いますよね」「あなたにはトラウマがあるのでは」「ちゃんと理解できましたか」
- 司会者が困った人の代わりに選ぶことはせず、参加者の自尊心や占術への信念を評価しない。試験の対象は**作品の説明・UI**であり人ではない。
- 参加者が不安・苦痛・感情的負担を示した場合はその場で課題を止め、継続意思と支援ニーズを本人に確認。医療的診断や救済の保証はしない。

## 6. 評価票と尺度（D/I：心理尺度ではない）

回答形式：以下すべて「1 全くそう思わない／2 あまりそう思わない／3 どちらともいえない／4 ややそう思う／5 とてもそう思う／NA 該当しない／SKIP 答えたくない」。質問文の方向を揃え、NA・SKIPを3に置換しない。

### A群：無料の利用後評価（7項目）

| ID | 質問（本人の感じ方） | 評価の焦点 |
| --- | --- | --- |
| A01 | 最初の説明を読んで、どんな体験をするか分かった | 期待と説明 |
| A02 | 5問と画面の進め方は迷いにくかった | 操作性 |
| A03 | 結果の文章は読みやすかった | 可読性 |
| A04 | 結果が何を手掛かりに書かれたか理解できた | 納得感・透明性 |
| A05 | 自分の性格や人生を勝手に決めつけられたとは感じなかった | 非強制性・尊重 |
| A06 | 物語を読むこと自体を楽しめた | 楽しさ |
| A07 | 最後の問いは、答えても答えなくてもよいものに感じた | 自律性 |
| A08 | タイプなし・決めないの結果を読んで、置き去りにされた感じがなかった | 保留の納得。**保留画面体験者のみ** |
| A09 | 診断に登録・購入が必要だと誤解しなかった | 無料価値・誘導の正確性 |

自由記述（任意）：**一番好きだった表現／引っかかった言葉／迷った箇所／なくてもよさそうな説明／読み終えて何を考えたか／改善したいこと**。体験した実人生の事実は記載不要と明示。実際の引用は標準禁止。

### B群：有料候補の非個人サンプル評価（8項目）

| ID | 質問 | 評価の焦点 |
| --- | --- | --- |
| B01 | 商品説明で、何が届く想定か分かった | 提供内容 |
| B02 | 架空の見本文章は読みやすかった | 可読性 |
| B03 | 話の流れ（過去→今→これから）が追いやすかった | 物語構造 |
| B04 | 暦の象徴・本人の回答・創作の違いが分かった | 根拠と解釈 |
| B05 | 文章が人物の実人生を断定しているようには感じなかった | 断定リスク |
| B06 | 無料5問と有料候補の違いが理解できた | 商品差分 |
| B07 | 一つの読み物として興味を持てた | 楽しさ・魅力 |
| B08 | この説明と見本だけでは、購入判断に不足する情報があれば指摘できた | 取引条件・不安 |

追加の理解確認（自由回答）：**「この見本で実際に起きた出来事が証明されていると思いますか？」「商品として不足している条件は何ですか？」**。回答の正誤を責めず、表示に誤認を招く言葉がないか検査する。これらのスコアは妥当性が実証された心理尺度ではない。

## 7. 受容基準・改善優先度（D：暫定ヒューリスティクス）

**探索的な小規模レビューでは、百分率だけで合格判定しない。** 受容基準をあらかじめ決めるが「心理検査の有効性を証明」には使わない。

### P0〜P3問題の深刻度

| 深刻度 | 例 | 対応 |
| --- | --- | --- |
| **P0：停止** | 個人情報が無断送信、強い恐怖・傷つき、架空の人生事実を断定、未承認の有料課金、録音無断実施、本人以外のPDF閲覧 | 即時その試験を停止・安全対応、G1/G2はNO-GO。修正・再審査なしに再開しない |
| **P1：公開阻止** | 複数人にとって基本操作が不可能、保留を人格否定と理解させる、商品を科学的測定・的中保証と誤読させる、無料なのに登録必須と誤認 | 版を修正し、同じシナリオと異なる新規参加者で再テスト。残れば公開不可 |
| **P2：要改善** | 言い回しの読みづらさ、見出しやCTAの迷い、読む順序が分かりづらい | 修正PRとレビュー記録を残し、影響を受ける設問と文章を再検証 |
| **P3：改善候補** | 好み・意見が分かれる色、長さ、表現。明確な安全問題なし | 記録して次の版の仮説へ。少人数の好みを全利用者へ一般化しない |

優先度は**被害の重大さ×再現可能性×重要なタスクへの影響**をもとに人が決める。発生人数の多さだけでP0/P1を下げない。

### レビューの終了条件（研究1ラウンドとして）

- 全セッションで事前の明示同意を記録し、撤回と削除ルートが機能している。
- A群のシナリオA〜Eについて少なくとも1回ずつ実施し、結果・保留・全問xの読み取りの課題を把握。Fは画像未制作なら必ず未実施のまま記録。
- 必須課題O01〜O05が実際に観察され、重大な導線障害を把握した。
- B群は**商品説明と架空文章の概念評価**としてO06〜O08を実施し、有料本番文の評価済みとは書かない。
- A/Bそれぞれのスコアは**回答あり分母**とNA/SKIPを区別し、中央値と分布（nが小さければ人数表）を表示。「平均4.5だから合格」としない。
- P0/P1が1件でも発生したらリリース阻止。P2は修正を原則とし、未修正なら担当者が保留根拠を明示。単一事例でも重大なら優先。
- 参考の肯定傾向（4または5）は説明用の補助値のみ。初期案として**4/5以上を求める指標があっても、5人中4人に好評だから公開確定とはしない**。
- 無料G1の審査は**画像・スマホ・読み上げ・法務・情報管理・計測**などMK03/MK05/M11/M12の全ゲートを別に満たす必要がある。
- 有料G2は**本物の暦計算・検証済み物語品質・実際の決済・PDF納品・法律**などの全ゲートが別に必要。B群の架空コンセプト評価では一切解除されない。

## 8. 修正・再テストのルール（D）

1. 問題を匿名の「issue_id」で作り、対象画面／文面ID／M07/M08/M09版／シナリオ／症状の要約／深刻度／証拠参照（**非公開**）を記録。
2. 事実確認：同じ問題が開発者の手で再現するか。**再現しなくても当事者の不快や誤読を無視しない**。
3. 修正方針：コピー改善、CTA変更、UI／画像修正、説明追加、アルゴリズム改訂候補を分ける。質問・タグ・判定・画像版を変更するならDEVELOPMENT_RULESの正本・CIとM09のレビューを再実行。
4. 修正前／修正後、修正理由、影響したID、差分コミット、既存テスト結果をリンク。**レビュアーの観測を理由に暦の年や本人の過去を後出し変更しない**。
5. P0/P1は修正後に元と同等の再現シナリオ＋関連周辺シナリオを再実行。人への印象が問題だった場合は**別参加者による独立した確認**を少人数で行う。旧参加者へ再試用を強制しない。
6. 公式scene_v01画像が入ったら**Q1/Q2の文字代替プレビューの評価結果を画像版へ流用せず**、視覚・選択肢誘導とアクセシビリティの別ラウンドを実施。
7. 本番の暦候補年・本人の経験を使う鑑定評価は、M06/N01/N05の承認、必要データと同意・安全な研究系が完成してから別版で実施。現時点で実施したと書かない。
8. 修正済みでもM12の公開・販売審査で未合格なら公開禁止。判断者は「文章の好評」と「正確な計算・安全な運用」を独立に記録。

**版の反映**：M07 question_version、M08 algorithm_version、M09 copy_version、画像scene_version、UI build_commit、テストケース版、MK10 questionnaire_version を記録。変更のない領域に新たな科学的妥当性を付与しない。

## 9. データ構造・保存・削除（D：実運用前に法務・事業者確定）

| データ | 保存位置・案 | 保持・削除の案 |
| --- | --- | --- |
| 募集・調整の連絡先 | 担当者限定の非公開・暗号化された連絡管理。公開GitHubやCRMと分離 | **試験終了30日以内削除を初期案**。同意証拠等の必要記録は分離して保持根拠を確認 |
| 同意の証拠 | 参加者IDに紐づけ、説明書版・署名／明示選択・取得日時を保護領域で管理 | 法令上・説明上必要な期間を**運営責任者が決定**。一律の法定年限と断定しない |
| 課題観察・評価票 | 個人識別できる可能性のある擬名IDで非公開管理。録音録画なし、本人の事実詳細なし | **分析確定後90日以内に生メモを削除する案**。撤回対応・委託先・バックアップ実態と照合 |
| 匿名化済みの問題一覧 | 個人を特定できない要約だけ公開GitHubに記録 | 作品の品質履歴として管理。少人数の意見・個人特有の引用は公開しない |
| センシティブ情報の偶発取得 | 保存しない／不要な部分を即時削除し、必要なら当該セッションを中断 | 事故対応・法定の取扱いを確認。参加者から人生詳細を求めない |
| 再連絡希望 | 参加許可と別の明示意思・用途・期間 | 希望がなくなれば利用停止。広告メール登録と混同しない |

**匿名と仮名の違い**：参加者IDで連絡先と結べる評価記録は匿名ではなく**仮名化した個人情報**として保護する。公開できるのは再識別が難しい、十分に集約した論点のみ。少数群ごとの属性組合せや本人の生の引用で推測されないようにする。

**実施の最終前提**：募集フォーム・オンライン会議・録音・AI転写・クラウドDBなどのベンダーを決めたら、送信先・保存地・委託・外国移転・同意・情報セキュリティをMK05/MK07で審査。実サービスがないまま偽のプライバシー文言を公開しない。
