## 1. 事業上の決定と顧客（D/I）

- 主力仮説：**P-A 自己理解型**。占いや性格診断を楽しみ、自分の歩みや今の自分を決めつけられずに眺めたい人。28〜39歳女性は広告表現上の仮イメージであり実購買統計でも参加資格でもない。
- ブランドの一文（企画内部）：**キャラで興味を持ち、暦の象徴と今の自分の回答を分け、自分の歩みを物語として読み直す**。
- 共有キャラは入口・話題の素材、鑑定本文の主役は読み物。12×5の分類、AIを使うこと、無料であることは単独USPにしない。
- 本製品は心理テストの妥当性や未来の出来事の的中を保証しない。暦の計算再現性／占術上の解釈／本人の人生事実は別。
- 無料は**体験だけで完結**し、購入・連絡先登録で結果を人質にしない。有料は**長いだけではない個別の時間軸の読み物**を提供する。
- 商品名は作業名。名称・商標調査・ブランド表示の承認は別工程。

### 明示的なスコープ除外（D）

**無料v0.1に含めない**：出生12キャラの本番割当、60分類本文、年運・大運、出来事の推測、タイムライン、相性、ログイン、CRM登録の必須化、決済、PDF自動送信、自動SNS投稿、共有カードの生成、心理学的スコア表示、毎日の運勢。

**有料候補でも提供しない**：健康や疾病、犯罪、死期、妊娠、結婚・離婚の確定的予測、金銭的利益の保証、医学・心理検査・投資・法務判断の代行、本人の経験を聞いてから暦の候補年を遡及修正する行為。

**モバイルファースト**：縦スクロール中心。文字サイズ・タップ領域・文字と背景のコントラスト・読み上げテキスト・キーボード操作・戻る挙動・画面縦横の変化を確認。具体的な閾値はM11で試験環境とともに固定。

**画像が未完成の場合**：Q1/Q2の視覚体験をテキストで同一の検査をしたことに**しない**。原則公開保留。画像なし版を公開するなら、M07の質問意味と判定アルゴリズムの独立設計・レビュー・再テストを先に要求する。

**結果文の長さ**：スマホで読めることを優先し、テンプレートの句読点と重複を編集審査する。文字数はまず実機の可読性・利用者評価を優先し、根拠のない最適値は設定しない。

### 無料の納品・例外表示

- 結果の基本提供は**画面表示**。利用者の登録・メールアドレスを必要としない。
- 5問すべて「決めない」は有効な終了状態。タイプを偽って割り当てず、誰でも読める問いを返す。
- Q1とQ2だけが同じテーマでも、Q4と一致しなければタイプ保留（M08の既定ルール）。
- 戻ったとき選択肢が勝手に変化しない。中断・やり直しでは入力を破棄。現行の保存方針を実装で監査する。
- 読み込み失敗・バージョン不整合・入力改ざん時は**無理に鑑定文を出さず**、再試行や終了の案内を表示。
- 共有リンクを作る場合も出生情報・5問回答をURLに埋め込まない。v0.1には含めない。

## 5. 有料物語鑑定の詳細仕様（D：将来案、実装・販売不可）

### 5-1. 価値の最小単位

- **個別化の根拠**：承認済み暦計算と候補年選択規則の参照ID・版。年を言い当てる保証ではない。
- **本人の主体性**：本人は「当てはまる／少し／当てはまらない／覚えていない／回答しない」を選択可能。回答内容で候補年を改変しない。
- **物語品質**：特定年と象徴の関連・生活上の比喩・人間の矛盾・今のテーマを一つの中心概念で結ぶ。形式だけのタイプ説明を水増ししない。
- **信頼**：旧暦・節入り・時差・出生時刻等の適用範囲を示し、計算できないケースを有料提供対象にしない。

### 5-2. 画面フロー（概念）

| 画面ID | 画面 | 必須要素／例外 |
| --- | --- | --- |
| P00 | 商品説明LP | 対象者・提供範囲・サンプル・価格・限界・返金・サポート・販売者情報。価格等はMK04/MK05承認待ち |
| P01 | 入力前の条件確認 | 暦に対応する生年範囲、日本の民用日付、出生地・時刻等の必要性、保存条件を明示。入力できない場合は購入前に案内 |
| P02 | 必要情報入力 | 最小限の出生情報。本人確認・保留分岐。海外出生、暦境界など未対応は販売前にブロック |
| P03 | 暦由来の候補時期 | 承認済み候補年と根拠IDを先に確定。入力後の本人の回答で年を変更しない |
| P04 | 本人の照合・現在の回答 | 不一致・未回答を許容。5問の現在章は暦スコアと別レイヤー |
| P05 | 最終確認・決済 | 提供内容、納期、キャンセル、価格総額、連絡・支払方法。MK05/MK09の法令・決済審査後のみ |
| P06 | 鑑定本文表示・納品 | 章立て、表示する対象年・規則・限界、PDF納品、本人以外に漏れない取得方法 |
| P07 | アフターサポート | 受け取り確認、訂正依頼、問い合わせ、削除・再取得条件 |

**処理順と購入順を混同しない**：暦適用可否の判定は購入前。個人情報を保存する前に目的と保持・削除条件を案内する。処理順は計算→根拠固定→本人の照合→本文生成。決済をどこで行うかは安全性と提供可否を踏まえMK09で決定。

### 5-3. 鑑定本文／PDFの章立て

| セクション | 内容 | 注意 |
| --- | --- | --- |
| 表紙 | 作品名・鑑定の版・作成日。個人の識別情報は最小限 | 公開SNSに表示しない |
| この鑑定の読み方 | 使用した暦と独自解釈、対象期間、入力不足時の制限 | 科学的な的中保証ではない |
| 序章 | 今回の中心概念と、読み進めるための問い | 勝手に人生の事実を断定しない |
| 過去① | 根拠が確認できた候補時期・テーマ・生活の比喩 | 確認できない場合は省略／保留 |
| 過去② | 別時期のテーマと対照、変化の読み方 | 2時期を無理に捏造しない |
| 現在 | 本人の任意回答、5問からの現在章 | 暦と自己申告を混ぜた心理得点を作らない |
| これから | 検算済みの将来暦テーマを本人の選択肢として提示 | 未来年の計算不可なら章を削除 |
| 結び | 最初の問いへ戻る、一つの小さな振り返り | 行動を強制しない |
| 計算・解釈の注記 | 方法・根拠ID・版・対象年・不明条件 | 専門用語を読みやすく説明 |

分量は既存[年運物語の編集仕様](../13-annual-story-engine-design-v0.1.md)にある**本文1,500〜2,000字を初期の編集目安**とする（PDFの注記は別）。満足・読みやすさ・工数は実測で調整。年数や字数の過剰な約束をしない。

**PDF主納品候補**：日本語文字が選択・検索可能、見出し構造、改行、スマホでの可読性、必要に応じる適切な代替テキスト。閲覧・印刷・紛失時の取り扱いをMK09で決定。開発物から実在する利用者の出生データを含むPDFは作らない。

### 5-4. サンプル仕様

サンプルは実在人物の生年月日・実人生・架空の「的中年」を用いない。**架空例のデータであること**を表題から明示し、開発中の画面や文章を販売可能な結果のように示さない。

展示可能な文章の骨組み（個人鑑定ではない）：
> 架空の読み物サンプル：ある年を境に、続けてきたことを少し見直したくなる場面があります。これは暦の候補時期を生活の比喩へ置き換えた例であり、特定の人に実際に起きた出来事を示しません。今の自分なら何を大切にしたいか、問いを残します。

実際の商品ページでは、完成した鑑定書の実際のページ数・章・取得方法が確定した後に、その仕様通りの非個人サンプルを掲載。

## 6. 情報・結果の最小データ契約（D：設計案）

### FREE-01

- 入力：質問バンク版、Q1〜Q5の選択／明示的な「決めない」、同意・説明確認状態。**氏名、出生情報、メールを受け取らない**。
- 処理：M08のタグ・保留ルール、M09表示関数、版整合。独自の心理得点は作らない。
- 出力：status（complete／type_pending／incomplete／error）、現在テーマID、タイプ候補ID（nullable）、フェーズID（nullable）、文章・問い・注記。
- 保護：回答列や端末の識別子をイベント分析へ載せない。意図しない保持や第三者送信をしない。

### PAID-01（将来）

- `source_schema_version`、`calendar_method_version`、`birth_boundary_status`、`calendar_evidence_refs`、`candidate_years[{year,rule_id,evidence_refs}]`、`user_reflection_status`、`writing_dictionary_version`、`reading_template_version`、`render_status`、`delivery_version` を版付きで保管できるようにする**構想**。
- 対象年は「計算規則・承認版・暦の根拠」の3点を満たすときのみ採用し、未対応は `timeline_unavailable` や購入前の `not_supported` として分岐。
- 有料商品の適用範囲未達時に、無料の現在章へ勝手に差し替えて**同じ商品として代金を徴収しない**。販売前に止めるか、本人が了承した別商品に変更する。後者は別の明示的取引条件が必要。
- LLMは渡された根拠ある候補年と表現辞書の範囲で文章編集に使う余地のみ。計算・候補年の事後生成・本人の実人生の捏造は不可。
- 顧客の出生情報・相談・決済情報を公開GitHubへ保存しない。実際のデータ保持主体・期間・削除はMK05/MK07/MK09が正式決定。
