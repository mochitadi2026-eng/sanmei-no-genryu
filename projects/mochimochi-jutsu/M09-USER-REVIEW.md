### ローカルでの起動

このリポジトリをチェックアウトしたPCで、ルートから次を実行する。

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

ブラウザーで `http://127.0.0.1:8765/projects/mochimochi-jutsu/m09-preview.html` を開く。

HTMLファイルを`file://`で直接開くとJSONの読み込みが制限されるため、HTTPサーバーを使う。Node等でローカルHTTPサーバーを立ててもよい。この手順は**実行方法の案内であって、今回ローカルの実機を実行した証拠ではない**。実際のブラウザ動作確認はCIのログと明示的に切り分ける。

## 文章評価：確認したい5つの問い

利用者への説明は「5問で選んだことを、今の自分を考える材料として眺める体験です」。本人の性格を言い当てる検査だと誤認させない。

1. **分かりやすさ**：読んで、自分がどの回答をした結果なのか分かったか。
2. **決めつけの少なさ**：人格、能力、運命を勝手に言い当てられた感じはなかったか。
3. **未判定の納得感**：タイプ名がつかなかった場合でも、内容を読んで損した／否定されたとは感じなかったか。
4. **役立ち方**：最後の問いかけは考える材料になったか。不要であれば気軽に無視できるか。
5. **操作性と安心**：5問・戻る・中断・「決めない」が理解できたか。回答の保存・共有の説明に不安はなかったか。

初期の品質点検として**少人数（目安5～8人）の自主参加者**に見てもらい、上記5項目を「分かった／少し迷った／分からなかった」と自由記述1件で確認するのは一案。これは探索的な文章レビューで、心理尺度の妥当性確認や統計的な代表性の証明にはならない。人数は実施計画の案であり、参加した人数ではない。

### 人が試すときの具体的なシナリオ

- **A：タイプあり**：Q1=a、Q2=x、Q3=c、Q4=a、Q5=a → MT01・FP03。見出し／タイプの仮称／今のフェーズ／問いの意味を点検。
- **B：タイプ保留**：Q1=a、Q2=a、Q3=c、Q4=b、Q5=a → 未判定だがMOCHI・KETSU・FP03の記述が読み取れるか。
- **C：全問「決めない」**：5問すべてx → 名前なしでも自然に読み終えられるか。
- **D：モード保留**：Q1=a、Q2=x、Q3=x、Q4=a、Q5=x → テーマは残り、タイプ・フェーズは保留。
- **E：実際の任意回答**：選択肢に無理に合わせず、ひとつでも当てはまらない時に`x`を使えるか。録画、実氏名、誕生日を収集しない。
- **F：画像の検証**：画像`scene_v01`完成後に実施。それまでは**未実施**と明記。

## 記録ルール・品質ゲート

- 収集は任意同意を取って実施し、実名・生年月日・自由記述の生データを公開GitHubに置かない。結果が公開になると案内するなら本人の別同意を得る。原則は**匿名化した集約的な発見のみ**記録する。
- [ ] 5問を通して表示する**実ブラウザの自動検証が成功**している。
- [ ] 文字の読みやすさ、スマートフォンの表示、キーボード移動、スクリーンリーダー操作などを実機で確認。
- [ ] シナリオA〜Eの手動レビューを少なくとも担当者が行い、矛盾や不自然な表現を記録。
- [ ] 自主参加者の文章レビューを実施し、各問の気づき・問題・改善案を記録（**まだ未実施**）。
- [ ] 指摘が見つかったら、文章IDと版を更新し、M09のテスト・ブラウザ確認を再実行する。
- [ ] 画像未制作の影響を区別し、画像が完成したらQ1・Q2に関する確認を再度実施。
- [ ] **公開URL・保存機能・SNS共有を有効化する前にM12の同意・法務・安全審査を実施**。本番へ勝手に接続しない。
