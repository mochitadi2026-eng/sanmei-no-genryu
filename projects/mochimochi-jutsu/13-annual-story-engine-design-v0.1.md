# もちもち占術｜暦から「過去の伏線」を選んで鑑定文を作るシステム v0.1

起案：2026-11-03
優先順位：**鑑定文を先に作る。もちキャラは最後のSNS共有用。**
進捗：**仕様設計。大運・年運の転機判定式は未確定、個人の実鑑定データ生成は未実装。**

## 0. 何を自動化するのか

AIへ「1987年4月25日生まれをしいたけ占い風に鑑定して」と渡す方式は禁止。年を都合よく作り、経験を言い当てたように文章を合わせる危険がある。

代わりに以下の順序を固定する。

```text
[出生情報・本人の入力] （保存原則なし）
        |
        v
A 暦計算エンジン（M06、採用する方式と版）
 年・月・日干支／大運の切り替え／年の干支
        |
        v
B 年ごとの暦シグナル計算（新規、R層）
 その年に何が重なったかをrule_idと根拠で列挙
        |
        v
C 物語アンカー選定（独自の編集上の評価、O層）
 過去20〜30年から2時期、これから1時期を選択
        |
        v
D 象徴→日常の意味へ翻訳する辞書（O層）
 中心テーマ1つ、対照テーマ、生活場面、迷い
        |
        v
E 鑑定文組み立て（決定論テンプレート、任意でAIが推敲）
 具体年→矛盾→日常場面→過去の意味変化→現在の5問→未来
        |
        v
F 検証（自動監査＋読者レビュー）
 年の捏造防止、出典、文章の反復、読み応え、未判定の尊重
        |
        v
G もちキャラの共有カード（本文・暦とは別）
```

**Bの年運シグナルの意味づけは未着手**。N01で2024〜2027年の立春に基づく年干支の記号部分のみ実装済み（[史料・検証範囲](14-n01-daiun-nenun-sources-and-implementation-2026-11-03.md)）。年柱・日柱の計算だけでは「転機」を決める根拠がない。現代算命学の大運・年運の計算・意味づけは採用流派を決めて別途検証する。2019年など特定年を勝手に転機にしない。

## 1. 最小入力データ契約（案）

```json
{
  "schema": "annual-reading-v0.1",
  "as_of_year": 2026,
  "calendar": {
    "status": "needs_audit",
    "method_version": null,
    "branch_ref": "tadi-sanmei-desk:PR#29",
    "sources": [],
    "birth_boundary_status": "unverified"
  },
  "annual_signals": [
    {
      "year": 2020,
      "rule_id": "RULE_PENDING_AUDIT",
      "symbol": "DUMMY",
      "theme_id": "T_RECONSIDER",
      "source_refs": [],
      "is_fixture": true
    }
  ],
  "questionnaire": {
    "source": "M08",
    "type_id": null,
    "phase_id": null
  }
}
```

**このJSONは資料用の架空例**。2020年が特定の個人にとって転機である意味ではない。

本番データに必須の条件：
- `calendar.status`が単なる自己申告でなく、承認済み版・CI・一次資料への対応で確認できること。
- 年・月・大運の区切り、出生地の時計制度、日界、節入りを解決できるか。境界保留なら無理に確定しない。
- `rule_id`が固定した辞書にあり、その規則がどの暦記号からどの解釈を導くのか再現できること。
- 命式の情報を自由なLLM作文の中で推測・逆算させないこと。
- M08現在の5問とM06出生由来の値を同じ得点に加算しないこと。

## 2. 候補年の抽出ルール（実装候補・占術上の公式ではない）

第一段階では、現在から過去25年（成人後だけに限定しないが幼少期は別表示）に対して各年の確定したシグナルを列挙する。誕生前年・未来年・計算範囲外の年は除く。

候補選定スコア（**これは暦的な吉凶点数でも性格得点でもなく、文章の題材を選ぶ編集用ルール**）：

| 条件 | 編集上の重み | 備考 |
| --- | ---: | --- |
| 採用済みの10年単位の運の境界がその年にある | +5 | 大運計算が承認されてからのみ有効 |
| その年に異なる2規則のシグナルが重なる | +3 | 同じ規則の重複カウント禁止 |
| 前後に異なるテーマへ切り替わるという定義済み規則がある | +2 | 事後に好きな意味を選ばない |
| 直近の5年に該当する | +1 | 読者が振り返りやすいという編集仮説 |

- **重みは仮説**。使う前に規則ごとの根拠・偏りを検証し、固定した版を持つ。現在のM06では大運境界が未承認なので+5を適用しない。
- 過去のアンカーは上位から**2時期**選び、通常**3年以上**離す。特定年が取れなければ1時期や保留を許可。
- 読者の過去の回答や後から聞いた出来事を使ってランキングを変更しない。
- 2時期を時系列に並べ直し、中心テーマが共通する場合のみ「繰り返した課題」として扱う。異なる場合は、**AからBへ意味が変化した**として書くか、無理に接続せず独立して記述する。
- 指標がないなら`timeline_unavailable`として今の5問だけを表示する。誕生日から適当な節目を作らない。

**重要：スコア選定の前に、占術規則と暦計算の実証が必要。** この節の数字は固定された採用規則ではない。

## 3. 年号から文章への編集辞書（独自の執筆ルール）

いきなりLLMに「感動的に」と書かせず、編集者が以下の部品を準備する。

| テーマID | 中心概念 | 人間の矛盾 | 書ける生活場面（例示） | 禁止 |
| --- | --- | --- | --- | --- |
| T_RECONSIDER | やり方の再検討 | 続けたい／変えたい | 仕事の引継ぎ、朝の支度、慣れた場所への違和感 | 本当に転職したと断定 |
| T_EXPERIMENT | 小さな挑戦 | 試したい／失敗は怖い | 初めての習い事、知らない人への連絡、作りかけの企画 | 起業や結婚を事実認定 |
| T_CONNECT | 人との関係の組み直し | 一緒にいたい／距離も必要 | 返事を迷うメッセージ、誘いを断る瞬間 | 縁切り・別離の確定 |
| T_CONSOLIDATE | 育て直し | 広げたい／手元のものも大切 | 続いている習慣、小さな仕事の改良、予定の整理 | 成功や収入を保証 |
| T_REST | 余白の調整 | 頑張りたい／休みたい | 休めない休日、カレンダーの空き、時間の使い直し | 疾病や不調の診断 |

これらは**表現上の辞書**であり、暦記号との対応を決めたものではない。後でBのルールが検証できて初めて特定テーマへつなぐ。該当しない・曖昧な場合に当てはめない。

## 4. 鑑定文の組み立て仕様

目安1,500〜2,000字。ただし読了率を実測して調整。

**見出し／本文の役割分担**：

1. **序章（100〜180字）**：「この人の人生を読む中心概念」を引く。冒頭でタイプ名を言わない。
2. **第1章・過去の年①（300〜400字）**：年を実際に記す → 暦上のシグナルとテーマ → 生活場面を2つ → 人間の矛盾を1つ → 読み返す問い。
3. **第2章・過去の年②（300〜400字）**：年のテーマ → 先の年から変わったこと → 今の視点で再解釈。2年に一貫性がない場合は無理に伏線と呼ばない。
4. **第3章・現在（250〜300字）**：現在の暦テーマと5問の回答を**区別して**併記。5問のタイプ名は必要なら1行だけ。
5. **第4章・これから（300〜400字）**：検証できた年の象徴を1つ、実現を断定せず暮らしの選択肢に落とす。未来暦未計算なら章ごと保留。
6. **結び（100〜160字）**：最初の中心概念へ戻って短い余韻を残す。共有キャラへの誘導を本文の結論に入れない。

**推敲ルール**：
- 一篇に中心概念は1つ。補助概念は最大2つ。
- 特定年の選出根拠を文書としていつでも確認できる。
- 見出しに年があれば、その年について本文中に暦の説明・行動イメージがある。
- 一般的な励まし、読者の性格ラベルを連続させて文字数を増やさない。
- 「当てはまらなくても」の免責文は各段落で繰り返さず、振り返りの選択肢・末尾の明確な説明で担保。
- 文章がつながらない時、自然な段落にするために存在しないシグナルを追加しない。
- しいたけ占いの**構成技法**を参考にするが、文章・比喩・固有の言い回しは模写しない。

## 5. データ構造とLLMの役割

```text
calendarAdapter (M06：現時点未接続)
  → annualSignalRulebook (根拠付きルール：設計・検算待ち)
  → anchorSelector (年の選定を決定論化)
  → storyBlueprint (年・根拠・テーマ・対照・場面例の固定JSON)
  → storyRenderer (文章テンプレート；必要ならLLMで推敲)
  → factLinter (年の捏造・根拠のない事件・出生情報流出をチェック)
```

LLMへ渡すのは`storyBlueprint`の許可したフィールドだけ。LLMが生年月日から暦を計算したことにしない。出力時には許可した年以外の西暦を含む文章を弾く。単語のルールベース検査に加えて、人による読みを必須とする。

年の表示ができないときは、今の5問を読める**縮退モード**に切り替える。暦と5問を足した「性格スコア」は作らない。

## 6. テストと実利用で測るもの

- **暦エンジン**：独立した公的・一次資料との境界比較、対象年範囲、夏時刻・出生地、採用規則の監査。
- **候補年選定**：同じ入力で同じ候補、重複なし、根拠ID一致、過去年のみ、間隔制約、保留処理、本人の後付け回答に無関係。
- **文章**：年の捏造なし、禁止の断定／病気などの不適切な予測なし、M08未判定を尊重、未知のルールで段落を作らない。
- **人によるレビュー**：読み終えたか／気になる年を覚えているか／生活場面が具体的か／決めつけを感じないか／過去の年が当てはまらなかった場合にも理解できるか。
- **比較実験案**：同一の暦を用いた「タイプ説明中心」対「時間軸の物語中心」の2版を任意参加者に比較してもらう。まずは探索的な読みやすさの比較であり、占術の的中率を証明したと称さない。
- 個人の生年月日・過去の出来事・入力履歴を公開GitHubやSNSカードに保存／流用しない。

## 7. 次に実装する順序

| 順位 | ID | 成果物 | 実装成功と呼べる条件 |
| --- | --- | --- | --- |
| 1 | N01 | 暦シグナルの算出方式と採用範囲（M06の検算を含む） | 規則が資料・計算に戻れて、許可された年だけを確定 |
| 2 | N02 | 候補年選定器／架空fixtureでの試験 | 年が再現可能、2年の間隔、保留、根拠IDまで再現できる |
| 3 | N03 | 象徴から生活場面への文章辞書 | 語義に根拠／作者独自の比喩の区別と、全テーマに対照を用意 |
| 4 | N04 | `storyBlueprint`と文章出力器 | 正しい年以外の追加、別の人物の人生事実の捏造を防止 |
| 5 | N05 | 文章の実レビューとM11接続 | 未判定／保留／通常ケースの読み味と事実表示を人が点検 |
| 6 | N06 | もちキャラ共有カード | 本文とは分離。本人の年月日・具体的な過去・回答の共有は不可 |

**N01で2024〜2027年の立春境界と年干支だけ部分実装。M06と大運の採用規則が保留のため、N02の選択器は架空fixtureでしか検証できない。実ユーザーの転機年や大運開始年齢を算出・配布したと扱わない。**
